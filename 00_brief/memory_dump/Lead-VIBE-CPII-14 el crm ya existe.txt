### 2. DOCTRINAS TÉCNICAS
* **Doctrina Skeleton (Global):** Separación radical entre la capa visual y la lógica (`Artifacts`).
* **R3 (Zero Hex):** Prohibición absoluta de usar colores hexadecimales (`#fff`, `#1e1b14`) en JS o CSS inline. Obligatorio el uso de Custom Properties (`var(--theme-...)`) para garantizar la permeabilidad del Modo Oscuro.
* **R4 (i18n Estricto / Agnóstico):** Ningún texto hardcodeado en UI base. Todo usa `data-i18n` conectado al core, excepto los Web Components masivos (Manuales) que usan el Modelo Autónomo. Uso de tokens dinámicos como `[CLUB_NAME]`.
* **Arquitectura Trinity:** Órbita 1 (Sidebar estático 250px), Órbita 2 (Workspace Canvas fluido), Órbita 3 (Right Dock AIMON 320px).
* **Protocolo `/laparoscopia` (v3.0):** Intervención quirúrgica en 3 actos (Declaración, Mapa de Coordenadas, Ejecución por Bloques con Código Anterior/Nuevo).
* **Zero-Server & Vanilla JS:** Sin frameworks reactivos pesados, sin build steps complejos. Todo se monta en Light DOM o inyección nativa.

### 3. INVENTARIO DE LO CONSTRUIDO
* **Motor i18n v2.0** — Gestor de internacionalización sincronizado. Lee `cpii:locale`, expone `window.__CPII__.i18n.t()`, y dispara evento global `cpii:lang:change` sin recarga. — Ubicación: `core/i18n.js`
* **Web Component gd-manual v2.0** — Gadget del Manual de Buenas Prácticas (8 secciones). Implementa el "Modelo Híbrido Autónomo", escuchando `cpii:lang:change` para inyectar plantillas propias sin depender de `data-i18n`. Renderizado en Light DOM. — Ubicación: `gadgets/gd-manual.js`
* **Handoff de Estado Universal** — Tubería de persistencia que conecta `localStorage` -> URL params -> `at-bootstrapper` -> Firestore (preferencias de `lang`, `theme`, `timezone`). — Ubicaciones: `core/at-bootstrapper.js`, `core/handoff-emitter.js`
* **Tab Manager (Base Órbita 2)** — Gestor de pestañas con persistencia volátil en `sessionStorage` e inyección en Canvas. — Ubicaciones: `core/at-tab-manager.js`, `css/tab-manager.css`

### 4. DECISIONES DESCARTADAS Y POR QUÉ
* **Shadow DOM Cerrado/Abierto en Gadgets:** DESCARTADO. Kimi y Qwen lo intentaron. Bloquea la cascada de variables CSS (`var(--theme-*)`), rompiendo el Modo Oscuro y aislando el componente del ecosistema visual. Se usa Light DOM.
* **Destrucción del DOM en Cambio de Pestaña (`innerHTML = ''`):** DESCARTADO. Destruía el estado del usuario (inputs, textareas). Se sustituye por persistencia volátil (ocultar/mostrar nodos con CSS) para mantener el estado vivo mientras dure la sesión.
* **Diccionario Global Único (`i18n.js`) para contenido masivo:** DESCARTADO. Generaría un archivo inmanejable. Para documentos largos como el Manual, se adopta el "Modelo Híbrido Autónomo" (el gadget contiene sus propias plantillas ES/PT/EN/FR).
* **Uso de la clave `cpii_crm_lang`:** DESCARTADO. Provocaba amnesia de idioma al no coincidir con el bootstrapper. Unificado a `cpii:locale`.

### 6. CONOCIMIENTO TÁCITO DEL PROYECTO
* **Perfil de la Interfaz:** El cliente (Lux Lusitana / Inversores Inmobiliarios) requiere extrema sobriedad. Diseños con "colorines", florituras o aspecto poco profesional causan rechazo inmediato. Todo debe transmitir lujo sobrio, seguridad y eficiencia (blancos, negros, grises, acentos dorados/azules oscuros).
* **Gestión de Agentes (Junior Devs):** Kimi, Qwen y Perplexity tienen buena lógica algorítmica pero nula disciplina visual (violan R3 constantemente). Por ello, han sido desterrados del DOM visual y reasignados a la unidad "Artifacts" (procesamiento backend simulado, utilidades, data entry).
* **Agnosticismo del Código:** El sistema está diseñado para ser multitenant ("BreederHub"). Se deben usar siempre placeholders como `[CLUB_NAME]` en lugar de nombres fijos, salvo orden directa del Director.
* **Tono de Trabajo:** Entorno industrial táctico. Se valora la precisión, la obediencia estricta a protocolos (`/laparoscopia`) y la ausencia de condescendencia o exceso de cortesía.
