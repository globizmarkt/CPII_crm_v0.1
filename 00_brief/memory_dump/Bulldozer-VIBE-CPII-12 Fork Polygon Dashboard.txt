## 2. DOCTRINAS TÉCNICAS

### Globales (Skeleton v2.5)
- **R3 Zero-Hex:** Prohibido usar valores de color hexadecimales directos en CSS. Todos los colores deben referenciarse mediante CSS Custom Properties o tokens de diseño.
- **R4 i18n:** Prohibido hardcodear literales de UI. Todo texto visible debe pasar por el sistema de internacionalización del proyecto.
- **Vanilla First:** CERO frameworks JS. CERO librerías externas de estado. Web Components nativos (Custom Elements API + Shadow DOM) como única abstracción de componente permitida.
- **Compliance Firestore:** Aislamiento estricto por `tenant_id`. Ningún bypass de seguridad sin registro de auditoría inmutable.

### Específicas emergidas en sesión
- **Event-Bus por Canal:** `EventTarget` como singleton por dominio de evento (`getChannel('alertas')`). `CustomEvent` siempre con `{ bubbles: true, composed: true }` para cruzar Shadow DOM. Prohibido `window` como bus.
- **Layout Splitters 60 FPS:** Toda lógica de drag-resize debe desacoplarse con `requestAnimationFrame` + función `Lerp`. Regla CSS `contain: layout` obligatoria en paneles redimensionables para evitar layout thrashing.
- **Auth Dual Path:**
  - *Warm Path:* Custom Claims (`polygon_operator: true`) — lectura transversal estándar, propagación asíncrona aceptada.
  - *Hot Path:* Cloud Function Callable que emite Custom Token temporal (15 min) para cruzar `tenant_id` en auditorías de emergencia. Registro inmutable obligatorio en Firestore por cada emisión.

## 4. DECISIONES DESCARTADAS Y POR QUÉ

| Decisión | Motivo del descarte |
|---|---|
| `window` como Event-Bus global | Contamina el espacio global, imposible aislar canales por dominio, genera colisiones en arquitecturas multi-componente con Shadow DOM |
| Frameworks JS (React / Vue / Angular) | Violación directa de restricción inmutable Vanilla First — no debatible |
| Custom Claims como único mecanismo de Auth transversal | Propagación asíncrona de hasta 1 hora inaceptable para auditorías de emergencia → solución Hot Path complementaria |
| Layout thrashing con `mousemove` directo en splitters | Provoca reflows síncronos, colapso a <60 FPS en paneles complejos → sustituido por RAF + Lerp |
| Colores hex directos en CSS | Violación R3 Zero-Hex — no debatible |

## 6. CONOCIMIENTO TÁCITO DEL PROYECTO

- **Polygon Dashboard es capa transversal, no vertical:** Vive *por encima* de CPII y CIFI-AIP. Cualquier componente que se construya debe ser agnóstico al negocio vertical — no puede asumir contexto de ninguna de las dos plataformas.
- **El Lead Architect (Gemini) tiene veto bloqueante:** No es un rol consultivo. Ninguna intervención de más de 1 archivo se ejecuta sin su validación. En la práctica, esto significa que el flujo real es: Director emite orden → Bulldozer diagnóstica → Lead Architect valida → Bulldozer ejecuta.
- **WebOS GLOBIZMARKT como contexto producto:** El Polygon Dashboard es la interfaz operativa de un sistema más amplio (GLOBIZMARKT). Las decisiones de UX no son caprichosas — responden a un ecosistema de múltiples verticales con operadores reales.
- **`tenant_id` es el eje de seguridad central:** Todo dato en Firestore orbita alrededor del `tenant_id`. Cualquier lógica que cruce ese límite —aunque sea legítima— es un evento de auditoría, no una operación ordinaria.
- **El bypass de emergencia (Hot Path) es una válvula, no una puerta:** Su existencia está justificada operativamente, pero debe tratarse como superficie de riesgo. El registro inmutable no es opcional — es la condición que hace aceptable el bypass.
- **Nomenclatura de clases CSS es semántica y contractual:** `wd-` (widget), `gd-` (grid) son prefijos de dominio, no estética. Improvisar nombres fuera de este sistema rompe el contrato con otros agentes que consumen el mismo markup.
- **Los agentes de consulta tienen dominio asignado:** Perplexity → Event-Bus. Kimi K2.5 → Auth/Rules. Qwen → UI/render. Cruzar dominios genera ruido y respuestas menos precisas — respetar la asignación.
