## 2. DOCTRINAS TÉCNICAS

**Reglas Globales Skeleton Factory (R0–R5) — INMUTABLES:**
- R0: Sin hardcode — variables desde manifest
- R1: Trinity Layout — Órbita 1 sidebar 250px | Órbita 2 Canvas | Órbita 3 Inspector 320px
- R2: Taxonomía de componentes con prefijos aislados (ver abajo)
- R3: ZERO HEX — únicamente `var(--theme-*)` para colores
- R4: ZERO texto plano — `data-i18n` obligatorio en todos los nodos de texto
- R5: Firestore proyecto `cpii-landing` como capa de datos centralizada

**Taxonomía de Componentes (R2 ampliada — aprobada sesión 2):**
- Widgets `.wd-*` → Órbita 3 (Inspector). Persistentes. Se inyectan una vez. Ej: AIMON, Gatekeeper
- Gadgets `.gd-*` → Órbita 2 (Canvas). Bajo demanda. Se abren, se usan, se cierran. Múltiples instancias posibles
- Artifacts `.at-*` → Capa lógica profunda. Sin UI directa. Orquestadores. Ej: bootstrapper, tab-manager, signer, uploader

**Doctrinas emergentes no codificadas oficialmente:**
- Los gadgets deben preservar estado (scroll, inputs) al cambiar de pestaña — show/hide, nunca destroy/recreate
- El Canvas es un navegador moderno: Tab Bar superior, gadgets como pestañas
- i18n se aplica también después de inyección dinámica — siempre llamar `applyTranslations(lang)` tras `innerHTML =`
- Rutas de fetch en Vercel son relativas sin `../` — `fetch('gadgets/gd-manual.html')` no `fetch('../gadgets/...')`

## 4. DECISIONES DESCARTADAS Y POR QUÉ

- **`hidden md:block` para ocultar Admin Gate en móvil** — Tailwind CDN no compila clases responsivas dinámicas. Descartado. Pendiente resolución con inline style o detección JS
- **Sección 8 del manual (textarea de valoraciones)** — Descartada por el Director. El canal oficial de feedback es nota de audio por WhatsApp, no formulario en el CRM
- **`../gadgets/wd-manual.html` como ruta de fetch** — Ruta relativa incorrecta en Vercel. Corregida a `gadgets/gd-manual.html`
- **Prefijo `wd-` para el manual** — Incorrecto taxonómicamente. El manual es un gadget (Órbita 2 bajo demanda), no un widget (Órbita 3 persistente). Renombrado a `gd-manual`
- **Tema oscuro para el Canvas** — El Director quiere zona de estudio con fondo crema y texto oscuro. El Canvas usa `bg-background-light`
- **Destroy/recreate de gadgets al cambiar pestaña** — Patrón descartado en favor de show/hide para preservar estado

## 6. CONOCIMIENTO TÁCITO DEL PROYECTO

- **El "Principio del Profano"** es el concepto rector del negocio: el prescriptor no explica, solo abre la puerta. El experto toma el relevo en el webinar. Todo el sistema de captación gira alrededor de esto
- **Dos tipos de webinar, dos audiencias distintas** — Webinar A para profesionales del sector (agentes/gestores/promotores), Webinar B para inversores externos. No mezclar mensajes entre audiencias es crítico
- **El MVP de onboarding es manual vía Telegram** — No hay automatización todavía. El equipo gestiona altas manualmente hasta que el negocio lo decida
- **El Director es el único que aprueba cambios doctrinales** — El Lead Architect (Antigravity SC) emite vetos bloqueantes pero no aprueba sin el Director
- **La identidad visual es gold-luxury sobre oscuro** en el CRM (Órbitas 1 y 3) y crema profesional en el Canvas (Órbita 2)
- **El proyecto tiene múltiples agentes** — Bulldozer (ejecución), Antigravity SC/Gemini (arquitectura), AITOR (memoria). El Director coordina todos. No asumir que el otro agente tiene contexto — siempre verificar
- **Dondominio** es el registrador del dominio `clubsocios.digital`. La propagación DNS tarda 15-30 minutos en la práctica
- **El repo GitHub es público**: `github.com/globizmarkt/CPII-crm_v0.1`
- **El Director trabaja en sesiones cortas e intensas** — prefiere cerrar hitos concretos en cada sesión antes de abrir nuevos frentes
