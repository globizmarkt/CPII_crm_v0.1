## DOCTRINAS TÉCNICAS
- **R3 (Zero-Hex):** Prohibido absoluto de códigos hexadecimales (`#FFF`, `#000`) en JS o CSS inline. Solo variables CSS (`var(--theme-...)`). Garantiza Modo Oscuro/Claro universal.
- **R4 (i18n Estricto):** Cero texto hardcodeado. Todo contenido visible debe usar atributos `data-i18n="clave"` o `data-i18n-placeholder`. Los textos viven en archivos de traducción, no en el código.
- **Zero-Server / Vanilla:** Sin frameworks (React/Vue/Angular). Todo nativo. Firebase se usa solo como backend invisible, no como ORM frontal.
- **Arquitectura Trinity:** Jerarquía de Órbitas. Órbita 1 (Layout), Órbita 2 (Canvas/Gadgets), Órbita 3 (Datos).
- **Shadow DOM Permeable:** Si se usa Web Components, el Shadow DOM NO debe bloquear la herencia de Custom Properties (CSS Vars). Si bloquea el tema, se considera defectuoso.
- **Persistencia Volátil:** El estado de UI (tabs, inputs) sobrevive a la navegación interna (hide/show), pero se limpia en F5. No hay persistencia local automática sin explícita orden.

## DECISIONES DESCARTADAS Y POR QUÉ
- **Shadow DOM Cerrado (`mode: 'open'` sin herencia)** — [Descartado] Bloqueaba las variables CSS globales (`--theme-surface-strong`), rompiendo el Modo Oscuro. Se requiere permeabilidad o Light DOM para estilos temáticos.
- **Fallbacks Hexadecimales en CSS** — [Descartado] `var(--color, #fff)`. Violación directa de R3. Si la variable no existe, debe fallar o usar `initial`, nunca un color hardcodeado.
- **Inyección Directa de Texto en JS** — [Descartado] `element.textContent = "Hola"`. Violación R4. Debe ser `element.setAttribute('data-i18n', 'key')` y delegar al motor i18n.
- **Destrucción de Nodos al Cambiar Tab** — [Descartado] `panel.remove()`. Perdía el estado del usuario (scroll, inputs). Se usa `panel.hidden = true` para preservar el DOM vivo.
- **Asumir Estructura del DOM** — [Descartado] Generar código sin leer `index.html`. Provocó selectores huérfanos (`.tab-bar` vs `#orbit-canvas`).
