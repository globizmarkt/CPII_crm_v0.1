### 3. DECISIONES GLOBALES DE ARQUITECTURA
- Agnosticismo Radical (R0) El motor Skeleton es whitelabel puro. Toda lógica de enrutamiento y pertenencia se inyecta vía Custom Claims (Mochila JWT).
- Zero-Hex & Tailwind (R3) Prohibido CSS custom o hex code. Diseño regido estrictamente por tokens `--theme-` y utilidades Tailwind.
- i18n Strict (R4) Texto hardcodeado prohibido. Toda cadena UI pasa por atributos `data-i18n` y diccionarios para mitigar XSS.
- Economía de Guerra (R5  Zero-Deps) Prohibido React, Vue o Redux. Lógica O(1) con Sets nativos. Firebase Gen 2. Descarte de LinkedIn de la Élite Federada por requerir infraestructura O(n).
- Compliance-Based Privilege Fricción en UI (Custody Hold) es intencional y opera como filtro de calidad (AMLKYC), no como defecto de usabilidad.
- Zero Trust UI (Born Locked) El DOM se despliega bloqueado por defecto (`data-gate-lock`). Solo el motor JS `passport-engine.js` tiene la autoridad de revelar contenido tras validar claims.
- Separación de Responsabilidades Bulldozer maqueta HTML (Estructura), Kimi electrifica JS (Lógica vía Light DOM), Qwen audita (Doctrina R2R3R4), Antigravity controla CorePersistencia. El Director es el único bus de datos.
- Protocolo de Laparoscopia Sin archivo real en contexto = sin operación. Qwen, Kimi y Antigravity tienen prohibido operar o emitir veredictos sobre fantasmas.
- Vía Manual Segura Se descarta el envío de códigos por WhatsAppTelegram (sesión sintética) para abrazar `sendSignInLinkToEmail` de Firebase, preservando el axioma JWT O(1).
- Erradicación de la Contaminación Inmobiliaria Todo artefacto debe estar respaldado por una coordenada física real en `MANIFEST.md` o `tree-breederhub.txt`.
