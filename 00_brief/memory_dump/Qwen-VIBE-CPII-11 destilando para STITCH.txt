## DOCTRINAS TÉCNICAS

**Globales (codificadas):**
- **R3 (Zero-Hex):** Prohibido colores hexadecimal hardcodeados. Usar `var(--theme-*)`
- **R4 (i18n):** Prohibido texto hardcodeado. Todo string debe pasar por sistema de traducción PT/ES/BR
- **Zero-Server:** Lógica de negocio en Cloud Functions, frontend es estado puro
- **Vanilla JS:** Sin frameworks externos. Tailwind CDN permitido para utilidades CSS
- **Arquitectura Trinity:** Canvas Central + Right Dock + Left Nav (órbitas definidas)

**Específicas de mi especialidad (emergidas en trabajo real):**
- **Doctrina de Firma Visible:** Todo schema JSON debe llevar firma ed25519 visible para auditoría
- **Doctrina de Clasificación UI:** Widget (efímero) ≠ Gadget (persistente) ≠ Artifact (soberano)
- **Doctrina Tierra Firme:** Los datos nunca desaparecen del DOM, se restringen con blur/overlay
- **Doctrina de Hibernación:** Gadgets deben poder minimizarse a icono sin perder estado
- **Doctrina KAIROS:** Whitepapers son inmutables post-auditoría, solo versionado hacia adelante

## DECISIONES DESCARTADAS Y POR QUÉ

| Decisión | Motivo del descarte |
|----------|---------------------|
| **Chart.js para Radar Chart** | Peso >150kb. Violación de principio de minimalismo. Reemplazado por Frappe Charts (~45kb) o SVG puro |
| **Fecha fija para AutofinancingClock** | Genera falsas expectativas. APY varía. Reemplazado por rango con intervalo de confianza (80%) |
| **Ticker manual sin aprobación dual** | Vector de desinformación. Reemplazado por sistema híbrido con validación de 2 roles ≥ Gestor |
| **Modo claro para WhitepaperViewer** | Rompe inmersión del WebOS. Reemplazado por serif optimizada para fondo oscuro (#161513) |
| **Kanban vertical para DealRoom** | Incompatible con viewport landscape. Reemplazado por horizontal con mini-map navigator |
| **Desaparición del DOM si Check 4 falla** | Genera confusión ("¿se borró mi deal?"). Reemplazado por blur + overlay accionable |
| **Polling cada 10s para ClubPulse** | Costo excesivo de lecturas Firestore. Reemplazado por polling 60s + Cloud Functions cron horario |
| **D3.js completo para PrescriptorTree** | Overkill para 3 niveles. Reemplazado por vis-network o SVG con virtualización |
| **Texto libre en Ticker entries** | Riesgo de inconsistencia. Reemplazado por plantillas pre-aprobadas para eventos automáticos |
| **Cálculo de comisiones en cliente** | Pesado para redes grandes. Reemplazado por pre-cálculo en Cloud Functions |

## CONOCIMIENTO TÁCITO DEL PROYECTO

**Restricciones de negocio no documentadas:**
- El mercado lusófono (PT/ES/BR) tiene regulaciones distintas de inversión — el sistema debe permitir toggles por jurisdicción
- Inversores BR requieren CPF válido, PT requiere NIF, ES requiere NIE — el Gatekeeper Check 1 varía por país
- El Fondo de Sostenibilidad (50% beneficio neto) es argumento de venta clave — debe ser visible en todos los dashboards
- "Autofinanciación mes 12-24" es el hook principal de retención — no puede fallar visualmente bajo ninguna circunstancia

**Sensibilidades del cliente:**
- El Director valora transparencia criptográfica sobre simplicidad UX (firma ed25519 visible > botón limpio)
- Hay resistencia a "parecer un MLM" — el árbol de prescriptores debe enfatizar "red de inversión" no "red de referidos"
- El término "off-market" es protegido — nunca mostrar deals públicamente sin Gatekeeper Check 4 completado
- WebOS no es metáfora, es arquitectura real — las ventanas deben comportarse como sistema operativo (hibernar, restaurar, cerrar)

**Patrones que funcionan:**
- Micro-interacciones en scores (animación al subir) generan engagement medible
- El candado visual en Gatekeeper reduce tickets de soporte en 40% (datos observados en conversaciones)
- Ticker automático genera más confianza que manual (percibido como "datos objetivos" vs "marketing")
- Dark mode no es preferencia, es identidad — cualquier desviación se percibe como error

**Trampas conocidas:**
- Firestore tiene límite de 10 lecturas/segundo por documento — ClubPulse puede excederlo si hay muchos inversores activos
- Tailwind CDN no es para producción — pero es decisión arquitectónica. No proponer build step sin autorización
- ed25519 en cliente requiere librería externa (tweetnacl.js) — añadir ~25kb. Decisión pendiente de Director
- Cloud Functions Gen 2 tiene cold start ~2s — no usar para paths críticos de UX (ej. login, deal open)

**Lo que un agente nuevo necesita saber:**
- Nunca commits directos a main — todo pasa por auditoría Qwen
- Los schemas JSON son contratos — cambiar un campo requiere versionado y notificación a todos los módulos
- "Director" no es título, es rol de aprobación final — sin su OK, no hay deploy
- La conversación con Bulldozer-br-claude es paralela — sincronizar memorias antes de Sprint 3
