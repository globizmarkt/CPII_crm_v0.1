## DOCTRINAS TÉCNICAS

### GLOBALES (OBLIGATORIAS)
- **R3 (Zero Hex)**: Prohibido `#fff`, `#000`, `#1e1b14`, etc. Solo `var(--theme-*)` y `var(--brand-*)` definidas en `input.css`.
- **R4 (i18n Estricto)**: Ningún texto visible hardcodeado en lógica. En Web Components autónomos: diccionarios internos ES/PT/EN/FR. En HTML estático: `data-i18n="clave"`.
- **Vanilla JS Puro**: Sin React, Vue, Svelte, ni librerías de estado. Solo API nativa: `CustomEvent`, `localStorage`, `fetch`, `Web Components`.
- **Zero-Server / Static Deploy**: Todo debe funcionar con Firebase Hosting + Vercel sin backend dinámico para UI.
- **Light DOM para Gadgets**: Sin Shadow DOM cerrado para permitir herencia de `var(--theme-*)` desde Tailwind global.
- **Persistencia Volátil**: Estado de gadgets se mantiene al navegar entre pestañas (show/hide), pero se limpia en F5 (no persistencia en localStorage salvo configuración explícita).

### ESPECÍFICAS DE MI ESPECIALIDAD (EMERGENTES)
- **Patrón Autonomous Component**: 
  ```js
  connectedCallback() {
    const lang = localStorage.getItem('cpii:locale') || 'es';
    document.addEventListener('cpii:lang:change', this._onLangChange);
    this.render();
  }

Tailwind JIT + CSS Vars: Para que Tailwind CDN no elimine clases con variables CSS, usar sintaxis arbitraria: bg-[var(--theme-surface)], text-[var(--theme-text)].
Registry-Driven Injection: Los gadgets no se hardcodean en el Tab Manager; se registran en RESOURCE_REGISTRY y se inyectan vía tabManager.open(tagName).
Idempotencia en Registro: Siempre envolver customElements.define() en if (!customElements.get('tag-name')).
Limpieza de Event Listeners: En disconnectedCallback, siempre remover listeners de cpii:lang:change para evitar memory leaks.

DECISIONES DESCARTADAS Y POR QUÉ
Decisión
Motivo del descarte
Usar Shadow DOM cerrado para gadgets
Bloqueaba la herencia de var(--theme-*) desde Tailwind global, rompiendo el Modo Oscuro. Se adoptó Light DOM con delegación de estilos.
Inyección destructiva (innerHTML = '') en Tab Manager
Destruía el estado de inputs y scroll al cambiar de pestaña. Se adoptó patrón hidden=true / display: none para persistencia volátil.
Hardcodear textos en lógica JS en lugar de diccionarios
Violaba R4 y hacía imposible la traducción dinámica. Se adoptó el modelo de diccionarios internos por idioma.
Usar colores hexadecimales como fallback en CSS
Violaba R3 y generaba inconsistencias visuales en Dark Mode. Se adoptó fallback encadenado: var(--theme-x, var(--theme-y, valor-defecto-seguro)).
Crear un Tab Manager embebido dentro de gd-manual.js
Confundía la escala: el manual es un gadget, no un navegador. Se separó: at-tab-manager.js es universal, los gadgets son contenidos.
Asumir variables CSS no documentadas (--brand-alert)
Riesgo de que el gadget se vea roto en producción si la variable no existe. Se requiere confirmación previa de Stitch o documento de variables.
Generar contenido especulativo cuando falta archivo fuente
Genera deuda técnica y pierde ciclos de revisión. Se adoptó regla: "Bloquear y solicitar input crítico antes de ejecutar".

OBSERVADA (NO MÍA, PERO CRÍTICA)
input.css no tiene documentación pública de todas las variables --theme-* y --brand-*. Esto obliga a asumir o adivinar, violando la doctrina de cero suposiciones.
at-tab-manager.js no tiene tests automatizados para verificar que no usa innerHTML = '' destructivo. Riesgo de regresión en persistencia volátil.
El sistema de eventos cpii:lang:change no tiene documentación de payload esperado (e.detail?.lang). Riesgo de que un gadget mal implementado rompa la reactividad.
No hay un script de validación R3 automatizado que escanee gadgets/ en busca de hexadecimales antes de deploy. Dependemos de revisión manual.
RESOURCE_REGISTRY no existe como archivo físico; es un concepto. Sin él, el Omnibox no puede indexar gadgets dinámicamente.

PATRONES QUE FUNCIONAN
Modelo Híbrido Autónomo: Los gadgets con diccionarios internos i18n + escucha de cpii:lang:change son más mantenibles que depender de un motor externo de traducción.
Registry-Driven Omnibox: Permitir que RESOURCE_REGISTRY defina qué gadgets existen, en lugar de hardcodear if/else en el Tab Manager, escala a 100+ recursos sin deuda.
Light DOM + Tailwind JIT: Usar bg-[var(--theme-x)] permite que las variables CSS penetren en los gadgets sin Shadow DOM, manteniendo el Modo Oscuro consistente.
TRAMPAS CONOCIDAS
Tailwind CDN elimina clases no usadas: Si usas var(--theme-x) en una clase arbitraria bg-[var(--theme-x)], asegúrate de que Tailwind no la purgue. En producción, puede requerir configuración explícita.
localStorage.getItem('cpii:locale') puede ser null: Siempre proveer fallback 'es' en la lectura inicial para evitar errores en primer render.
CustomEvent no es soportado en IE11: Pero el proyecto es Zero-Server moderno; si el cliente requiere soporte legacy, habrá que polyfillar.
Imágenes de Stitch tienen URLs de Googleusercontent con espacios: En el HTML real, los src de imágenes pueden tener espacios en blanco que rompen la carga. Validar y sanitizar antes de inyectar.
