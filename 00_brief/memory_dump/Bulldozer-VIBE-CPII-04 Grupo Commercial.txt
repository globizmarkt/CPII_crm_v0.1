## 2. DOCTRINAS TÉCNICAS

### Globales (aplicables a este proyecto)
- **R3 — Zero-Hex:** Sin colores hexadecimales hardcodeados en componentes nuevos. Usar siempre variables CSS o clases Tailwind del design system. Violación detectada: mi primer entregable `team-section.html` (standalone) usó `#0a0e1a` — corregido en versión integrada al usar las clases Tailwind del proyecto
- **R4 — i18n obligatoria:** Todo texto visible en producción debe tener `data-i18n`. Violación detectada en mi SEC-05 inicial (hardcoded) — corregida en v2 con 30 claves mapeadas. `equipo-comercial.html` es excepción aceptada como MVP-PT

### Doctrinas específicas emergidas en trabajo real
- **Motor i18n = leer antes de asumir:** El motor original usaba `textContent` puro (nunca innerHTML). Asumir `innerHTML` sin leerlo hubiera roto las bios con `<strong>`. Lección: siempre leer el motor antes de proponer cambios
- **data-i18n-html="true" = atributo explícito requerido:** El parche de Gemini v2.1.0 implementa la condición correctamente. Exactamente 2 nodos en el proyecto requieren este atributo: `team.da.bio` y `team.cb.bio` en `index.html`
- **Inline styles = deuda inmediata:** La propuesta de Gemini para el CTA usaba inline styles masivos. Aprendizaje consolidado: nunca inline styles en este proyecto — todo a clases Tailwind o al bloque `<style>` del HEAD
- **Design system del proyecto = Playfair Display + Manrope + 5 variables de color:** No inventar fuentes ni colores. El sistema está fijo en el Tailwind config del HEAD de index.html

## 6. CONOCIMIENTO TÁCTICO DEL PROYECTO

### Sobre el negocio
- **CPII** (Club Privado de Inversores Inmobiliarios) y **eXp Portugal Commercial Group** son dos entidades distintas pero relacionadas: CPII es el vehículo de inversión, Commercial Group es la estructura de agentes
- El acceso al grupo tiene criterios formales: Agente Senior (5 años, 75% negócios comerciais), Agente Especialista (3 años, 50%), Referenciador (cualquier miembro eXp). Esto no es marketing — es arquitectura de acceso real
- Las métricas de David Almeida (25% facturación, 7/17 CAPs, Agente del Año 2025) fueron validadas por negocio el 19/02. Fuente: actas de reunión del 18/02 con David Almeida y Carlos Balboa
- El grupo opera con exclusividad firmada para área Comercial Portugal — esto es un differentiator legal, no solo marketing
- La metodología KYC/AML no es un badge cosmético — es el filtro real que diferencia al grupo. Sin LOI + Prova de Fundos no se comparte información del activo. Antigravity y los demás agentes deben tratar esto como regla de negocio, no decoración

### Sobre el equipo de agentes
- **Gemini (Lead Architect):** Arquitecto de datos e i18n. Sus vetos son bloqueantes. Tiende a dar propuestas conceptuales sin código ejecutable — su fuerza está en el análisis y la arquitectura, no en el código entregable
- **Antigravity:** Agente de edición de código y deploys. Hace QA exhaustivo, genera auditorías por fases, gestiona ramas git. Altamente confiable para integración
- **GPT-OSS 120B:** Limpieza y fase 1. No interacciona directamente conmigo
- **Yo (Bulldozer):** Único agente que entrega código HTML/CSS ejecutable y listo para producción. La dinámica "Agentes Enfrentados" con Gemini es real — sirve para elevar calidad

### Patrones que funcionan
- Leer el archivo objetivo ANTES de cualquier str_replace — siempre
- Entregar código + diccionario i18n simultáneamente — evita el ciclo "falta el i18n"
- Usar `data-i18n-html="true"` como atributo explícito, nunca como comportamiento por defecto
- El Director aprecia respuestas directas sin preámbulo — modo BÁSICO por defecto, DETALLADO cuando hay arquitectura nueva

### Trampas conocidas
- **Trampa 1:** Asumir que el motor i18n soporta innerHTML sin leerlo. Coste: los tags `<strong>` se muestran como texto plano en producción
- **Trampa 2:** Entregar CSS standalone (con variables propias) cuando el proyecto tiene un design system Tailwind. El resultado no integra visualmente
- **Trampa 3:** Generar claves i18n sin ver el diccionario existente — riesgo de colisiones de naming o inconsistencia de estilo de claves (`snake_case` vs `dot.notation`)
- **Trampa 4:** Ignorar el parche XSS cuando se añaden traducciones con HTML interno. El motor original (v2.0.0) usaba textContent puro — cualquier valor con HTML era texto literal

### Stack técnico confirmado
- HTML5 + Tailwind CSS CDN v3 (plugins: forms, container-queries)
- Google Fonts: Playfair Display + Manrope
- Google Material Symbols Outlined
- Motor i18n propio (i18n.js) — localStorage persistence, 4 idiomas, DOMContentLoaded init
- Firebase (stack declarado en footer — no interactuado aún)
- Zero frameworks JS. Zero React. Zero Vue. Vanilla puro
- Git con ramas de feature — `main` protegido
