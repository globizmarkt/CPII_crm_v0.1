## 2. DOCTRINAS TÉCNICAS

### Globales del proyecto
- **R0:** Sin hardcode — variables desde manifest
- **R1:** Trinity Layout — Órbita 1 (sidebar 250px) | Órbita 2 (Canvas) | Órbita 3 (Inspector 320px)
- **R2:** Taxonomía: Widgets `.wd-*` | Gadgets `.gd-*` | Artifacts `.at-*`
- **R3:** Zero Hex — solo `var(--theme-*)`. Sin hexadecimales hardcodeados en JS ni CSS
- **R4:** Sin texto plano — `data-i18n` obligatorio (excepción: Web Components autónomos con Modelo Híbrido)
- **R5:** Firestore `cpii-landing` como capa de datos

### Doctrinas específicas emergidas en trabajo real

**R-B1 — Tailwind CDN nunca procesa clases `[]`**
`bg-[var(--theme-ink)]` no funciona en Tailwind CDN. SIEMPRE usar `style=""` inline para variables CSS. Las clases predefinidas (`bg-blue-900`) sí funcionan. Las arbitrarias con corchetes, nunca.

**R-B2 — Incisiones con apertura+cierre**
Cuando una incisión implica abrir Y cerrar un elemento HTML, entregar SIEMPRE el bloque completo con ambos extremos visibles. Nunca en partes separadas.

**R-B3 — Doctrina de tokens visuales**
Dos roles visuales, dos variables separadas:
- `--theme-border-active` → identidad de interfaz (dorado `#c1a85c`)
- `--theme-ink` → peso documental (índigo `#181d6d`)
Esta separación debe respetarse en todos los gadgets futuros.

**R-B4 — RESOURCE_REGISTRY siempre objeto `{}`**
Indexado por ID con prefijo `gd-`. NUNCA array. NUNCA IDs sin prefijo.
Lookup `registry[id]` es O(1) vs `registry.find()` O(n).

**R-B5 — Zoom en gadgets documentales**
Técnica: `font-size` en `rem` sobre contenedor `.manual-body`.
No afecta layout exterior. Escala proporcionalmente toda la tipografía.
Clave localStorage: `cpii:[gadget]:zoom`
Niveles canónicos: `[0.9, 1, 1.15, 1.3, 1.5]`

**R-B6 — Verificación antes de sellado**
Nunca declarar un archivo sellado basándose solo en el código de sesión.
Siempre pedir el archivo en disco y verificar con `view` antes del sello final.

**R-B7 — Modelo Híbrido Autónomo**
`core/i18n.js` → solo UI global (nav, estados, botones)
Web Components documentales → diccionario interno propio
Los gadgets documentales NO contaminan el core i18n con textos largos.

## 4. DECISIONES DESCARTADAS Y POR QUÉ

| Decisión | Motivo del descarte |
|---|---|
| `RESOURCE_REGISTRY` como array `[]` | Lookup O(n) con `.find()`. Sustituido por objeto `{}` indexado — O(1) directo |
| Shadow DOM en gadgets | Bloquea herencia de `var(--theme-*)` del tema global. Rompe Modo Oscuro. Descartado en VIBE-CPII-13 |
| Tab Manager embebido dentro de `gd-manual` | Convirtió el manual en un "mini navegador". El Tab Manager debe ser orquestador global, no componente local |
| `--theme-ink` en Tab Bar background | Generaba choque cromático frío-cálido con el sidebar marrón oscuro. Revertido a `var(--theme-surface)` |
| `--theme-ink: #0a1420` | Demasiado oscuro — casi negro, sin presencia documental real. Director eligió `#181d6d` |
| `--theme-ink: #0d1b3e` | Sugerencia de Bulldozer (azul marino FT/Bloomberg). Rechazada por el Director |
| Lógica de búsqueda en at-tab-manager | Crearía if/else gigante por cada recurso. Descartado — invertido a RESOURCE_REGISTRY + evento |
| Gradiente en Tab Bar | `linear-gradient(180deg, #1a1815 0%, #161513 100%)`. Violación R3 + doctrina anti-gradientes |
| cloneNode() para persistencia de pestañas | Destruía estado de inputs al cambiar pestaña. Sustituido por show/hide con `style.display` |

## 6. CONOCIMIENTO TÁCITO DEL PROYECTO

### Sobre el negocio
- CPII es un club privado de inversión inmobiliaria con operación en Portugal. El idioma primario es PT, pero el sistema debe funcionar en PT/ES/EN/FR
- El perfil de usuario incluye inversores mayores con posibles dificultades de visión — el selector de zoom A-/A+ no es un capricho, es una necesidad real de accesibilidad
- "Private Banking" no es solo estética — implica que los errores visuales (contraste roto, colores que fallan en modo oscuro) dañan la percepción de credibilidad del producto
- El KYC es una restricción regulatoria real, no un placeholder de demo

### Sobre el stack y el entorno
- El proyecto está desplegado en Vercel (`cpii-crm-v0-1.vercel.app`) con dominio activo `cpii.clubsocios.digital`
- Firebase/Firestore es la capa de datos del ecosistema landing. El CRM aún no está conectado (post-auth pendiente)
- Tailwind CDN sin compilador JIT es una restricción permanente — no es temporal. Diseñar siempre para este entorno
- El ecosistema tiene dos dominios: `cpii-landing` (Firebase) y `cpii-crm` (Vercel). El Handoff Emitter transfiere estado entre ellos via URL params

### Sobre el equipo
- El Lead Architect (Gemini) tiene tendencia a bajar a la trinchera y picar código directamente — esto ha generado hotfixes sin protocolo que rompen trabajo previo. El propio Lead Architect lo reconoció y se comprometió a respetar roles
- Antigravity es fiable para trabajo de volumen pero genera ocasionalmente código duplicado o llaves de cierre faltantes — siempre verificar su entrega antes de sellar
- Los Junior Devs (Kimi, Qwen, Perplexity, Mistral) tienen buena lógica pero poca disciplina visual. No confiarles incisiones en archivos con restricciones R3
- El Director (General Manager) es el árbitro final. Una sola palabra ("stop") paraliza todo

### Patrones que funcionan
- Protocolo uno a uno con autorización explícita elimina errores en cascada
- Pedir el archivo en disco antes de declarar sellado — el código en sesión y el código en disco divergen con frecuencia
- Reportar deuda técnica aunque no sea el objeto de la orden — el Director aprecia la transparencia
- Las capturas de pantalla del Director son diagnóstico — leerlas dos veces antes de responder

### Trampas conocidas
- `#orbit-canvas` vs `#canvas-orbita-2` — el ID del canvas en el DOM no coincide con el que el Tab Manager busca por defecto. Ya corregido pero puede reaparecer si alguien refactoriza el HTML sin actualizar el JS
- El `setTimeout(600)` de auto-apertura del Dashboard en versiones anteriores del Tab Manager — residuo que puede reaparecer en hotfixes
- `tabManager.open()` vs `tabManager.openFromRegistry()` — la API v2.x usaba `open()`. La v3.x usa `openFromRegistry()`. Cualquier código legacy que llame a `open()` fallará silenciosamente
- Los tags de búsqueda en RESOURCE_REGISTRY están solo en español — una búsqueda en inglés "operations manual" no encontrará nada
