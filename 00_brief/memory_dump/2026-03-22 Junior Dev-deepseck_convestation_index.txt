## 3. DECISIONES GLOBALES DE ARQUITECTURA

- **R0 — Agnosticismo Radical:** El núcleo (Skeleton) es 100% whitelabel. La lógica específica de negocio se delega a Custom Claims (“Mochila” JWT). Cualquier referencia a negocio se inyecta como configuración, nunca hardcodeada.
- **R2 — Light DOM:** Prohibido Shadow DOM. Los Web Components operan sobre Light DOM para heredar variables CSS y estilos globales.
- **R3 — Zero‑Hex:** Prohibido CSS personalizado o colores hexadecimales. Todo diseño y estado visual se resuelve con clases utilitarias Tailwind o variables `--theme-*`.
- **R4 — i18n Strict:** Cero texto hardcodeado en HTML o JS. Toda cadena visible al usuario debe ser clave de diccionario (`data-i18n`, `data-hold-i18n-key`) procesada por el motor de traducción.
- **R5 — Economía de Guerra (Zero‑Deps):** JS puro, cero dependencias externas (React, Vue, Redux, Zustand). Prohibidas Cloud Functions innecesarias. Preferencia por soluciones O(1) y escalado a cero.
- **Zero Trust UI (Born Locked):** La UI fiduciaria nace bloqueada visualmente (`data-gate-lock`). Solo `passport-engine.js` puede desbloquearla tras validar claims, previniendo FOUC.
- **Compliance‑Based Privilege:** La fricción en la UI no es un error; es un filtro de calidad AML/KYC. Las áreas bloqueadas (Custody Hold) son estado intencional.
- **Separación de Responsabilidades:** Bulldozer maqueta el DOM, Kimi electrifica la lógica en JS, Qwen audita cumplimiento doctrinal, Antigravity custodia el Core. El Director es el único bus de datos; prohibida comunicación lateral entre agentes.
- **Protocolo de Laparoscopia (“Sin archivo real = sin operación”):** Todo agente requiere el archivo físico en el contexto del chat antes de proponer o ejecutar modificaciones.
- **Erradicación de la Contaminación Inmobiliaria:** Ningún artefacto debe referenciarse sin una coordenada física válida en `MANIFEST.md` o el árbol de directorios.
- **Sidecar Architecture / Mochila:** La identidad y los permisos del usuario se encapsulan en `window.__CPII__.session`. El enrutamiento por `tenant_id` se resuelve desde los claims, no desde el código del Skeleton.
- **Tolerancia Cero a DT‑004/005:** El Sprint 4 (Golden Gate) no puede pasar a implementación sin tener Firebase SDK configurado y el motor i18n operativo con las claves necesarias.

## 5. CONOCIMIENTO TÁCITO CONSOLIDADO

- **El Director es el único Bus de Datos:** Los agentes son LLMs aislados. No comparten archivos, no se comunican mediante API ni modifican el disco local autónomamente. El Director humano copia y pega manualmente (Despacho Asincrónico).
- **Vibe de Alta Banca Suiza:** La aplicación exige un tono institucional, sobrio y discreto (“Luxury Glass”). Prohibidas dinámicas de startup o elementos lúdicos. La fricción en la UI (KYC lento, estados grises) es un “Escudo Psicológico” que filtra usuarios y comunica exclusividad.
- **Palabra de Seguridad (“guapito de cara”):** Gatillo de emergencia que valida la autoridad del Director en el entorno de desarrollo. Se emplea para superar bloqueos si se detecta deriva narrativa.
- **Ansiedad de Compilación del Lead Architect:** El orquestador estratégico tiende a generar código final o anticipar veredictos. La planta debe forzarlo a delegar y ceñirse a la orquestación.
- **Bifurcación Traccional de Usuarios:** Los Inversores interactúan con Lerium (landing) y no pasan por el Gate. Solo Staff y Partners utilizan la puerta fiduciaria (`golden-gate.html`), que es el objetivo del Sprint 4.
- **Inmutabilidad del “Hueso” (Skeleton):** Las reglas fundamentales R0–R7 son tratadas como un Código Penal. Cualquier incumplimiento (ej. un solo color HEX) genera rechazo inmediato.
- **Alucinaciones LLM Recurrentes:** Agentes secundarios tienden a proponer React, Redux, Shadow DOM o subcolecciones SQL-like. El Lead Architect y las doctrinas estrictas actúan como cortafuegos.
- **Paternalismo Sectorial / Escudo Psicológico:** “Restringir es demostrar valor”. Conceptos como “El Gate”, “Custodia Fiduciaria” imponen respeto y filtran agentes rebeldes.
- **La UI nace bloqueada:** El HTML estático muestra siempre `data-gate-lock`. El motor JS es la única llave que puede removerlo tras validación, previniendo FOUC.

## 6. GAPS DETECTADOS

- **Jurisdicción de Enrutamiento (Tenant Routing):** Pendiente decidir qué componente (y agente) será responsable de redirigir usuarios basándose en el `tenant_id` de los Custom Claims. Kimi señala que no pertenece a `passport-engine.js`; Bulldozer sugiere un nuevo `at-router.js` bajo Antigravity.
- **Resolución Técnica de `user.privateEmail`:** Aunque se aprobó Apple como proveedor de identidad, falta definir el flujo técnico de vinculación post‑login para mantener trazabilidad KYC cuando el usuario oculta su correo real.
- **Manejo de Errores de Fallback (`window.__CPII__`):** Múltiples agentes señalan el colapso silencioso si el objeto global falla, pero no se ha asignado un ticket claro para diseñar la UI de degradación.
- **Verificación Atómica UID-Phone:** Establecido conceptualmente que la Vía Manual debe requerir un teléfono pre‑registrado, pero no hay plan sobre cómo las reglas de Firestore validarán este vínculo antes de emitir el JWT.
- **Definición de “Éxito” del Sprint 4:** Criterios de aceptación para Golden Gate no están formalizados (¿qué validaciones son bloqueantes vs informativas?).
- **Documentación de la exclusión de LinkedIn:** Aunque decidido, no está formalmente registrada en los índices, lo que podría permitir que reaparezca en discusiones futuras.
