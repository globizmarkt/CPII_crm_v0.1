## 3. DECISIONES GLOBALES DE ARQUITECTURA

- **R0 — Agnosticismo Radical:** El núcleo (Skeleton) es 100% whitelabel. La lógica específica de negocio se delega a Custom Claims (“Mochila” JWT). Cualquier referencia a negocio se inyecta como configuración, nunca hardcodeada.
- **R2 — Light DOM:** Prohibido Shadow DOM. Los Web Components operan sobre Light DOM para heredar variables CSS y estilos globales. Los `onclick` inline son violaciones que deben ser saneadas.
- **R3 — Zero‑Hex:** Prohibido CSS personalizado o colores hexadecimales en producción. Todo diseño y estado visual se resuelve con clases utilitarias Tailwind o variables `--theme-*`. Excepción autorizada para Paper Mode (`#F9F8F1`, `#1A1A1A`) con aprobación explícita.
- **R4 — i18n Strict:** Cero texto hardcodeado en HTML o JS visible al usuario. Toda cadena debe ser clave de diccionario (`data-i18n`, `data-i18n-placeholder`). **Excepciones oficiales:** entornos de test (`*-tester.html`), logs de consola técnica, y el texto interno de un atributo `data-i18n` (fallback semántico válido anti-FOUC).
- **R5 — Economía de Guerra (Zero‑Deps):** JS puro, cero dependencias externas (React, Vue, Redux, Zustand). Prohibidas Cloud Functions innecesarias. Preferencia por soluciones O(1) y escalado a cero. Uso de `Set`/`Map` para validaciones, `setTimeout` asíncrono pasivo.
- **Zero Trust UI (Born Locked):** La UI fiduciaria nace bloqueada visualmente (`data-gate-lock`). Solo `passport-engine.js` o `at-admin-gate.js` pueden desbloquearla tras validar claims, previniendo FOUC.
- **Compliance‑Based Privilege:** La fricción en la UI no es un error; es un filtro de calidad AML/KYC. Las áreas bloqueadas (Custody Hold) son estado intencional.
- **Separación de Responsabilidades:** Bulldozer maqueta el DOM, Kimi electrifica la lógica en JS, Qwen audita cumplimiento doctrinal, Antigravity custodia el Core, Perplexity investiga, DeepSeek documenta, Lead Architect orquesta. El Director es el único bus de datos; prohibida comunicación lateral entre agentes.
- **Protocolo de Laparoscopia (“Sin archivo real = sin operación”):** Todo agente requiere el archivo físico en el contexto del chat antes de proponer o ejecutar modificaciones.
- **Erradicación de la Contaminación Inmobiliaria:** Ningún artefacto debe referenciarse sin una coordenada física válida en `MANIFEST.md` o el árbol de directorios.
- **Sidecar Architecture / Mochila:** La identidad y los permisos del usuario se encapsulan en `window.__CPII__.session`. El enrutamiento por `tenant_id` se resuelve desde los claims, no desde el código del Skeleton.
- **Exclusión definitiva de LinkedIn de la Élite Federada:** Descartado por violar R5 (requiere proxy O(n)). La trinidad nativa de Firebase (Google, Apple, Microsoft) es la única admitida.
- **Prohibición de parseo de URL en vistas HTML:** Queda estrictamente prohibido incrustar lógica de lectura de `window.location.search` en las vistas HTML. Cualquier captura de atribución debe implementarse en un módulo dedicado (`features/at-attribution.js`).
- **Doctrina de Autorización (RBAC):** Modelo de privilegios mínimos (Default-Deny). Todo usuario nuevo ingresa con `role: 'guest'`, `status: 'pending_approval'`. La UI muestra candados en todas las áreas excepto “Manuales”.
- **Cloud Run Functions v2 (Eventarc):** Obligatorio uso de `@google-cloud/functions-framework` en puerto 8080. IAM mínimo: `roles/datastore.user`, `roles/run.invoker`, `roles/eventarc.eventReceiver`.
- **Identity Platform Eventos:** Para que Firebase Auth dispare eventos hacia Eventarc, es mandatario activar la "Lectura de datos" y "Escritura de datos" en los Registros de Auditoría globales para Identity Toolkit.
- **Sincronización de tenencia canónica:** Se establece `tenant_id: 'cpii_lux_v1.0'` como identificador único de tenant en todos los artefactos (Custom Claims, Firestore, UI). Cualquier documento o sesión sin este valor es rechazado.
- **Inyección atómica de la Constitución Fiduciaria:** Cloud Function `onStaffCreated` asigna Custom Claims al registro: `role: 'guest'`, `status: 'pending_approval'`, `tenant_id: 'cpii_lux_v1.0'`.
- **Adopción absoluta del modelo Default-Deny en Firestore:** Reglas con función `belongsToTenant()` que compara `tenant_id` del JWT con el del documento. Fallback global `allow read, write: if false`.
- **Override doctrinal QA (R4 i18n):** Confirmado: el texto interno de una etiqueta con `data-i18n` es fallback semántico válido (anti-FOUC) y **no constituye violación de R4**.
- **Doctrina de Resilience (Polling Inverso):** Los componentes no asumen disponibilidad del core; reintentan asíncronamente (ej. `initTrinity` con `setTimeout` 100ms) para evitar race conditions en despliegues con latencia.
- **Recalibración estricta de Bulldozer:** Prohibición absoluta de emitir o tocar lógica JS o plantear decisiones estratégicas. Su jurisdicción se limita a DOM, atributos y clases Tailwind.

## 5. CONOCIMIENTO TÁCITO CONSOLIDADO

- **El Director es el único Bus de Datos:** Los agentes son LLMs aislados. No comparten archivos, no se comunican mediante API ni modifican el disco local autónomamente. El Director humano copia y pega manualmente (Despacho Asincrónico).
- **Vibe de Alta Banca Suiza — implicaciones para el DOM:** No hay elementos decorativos innecesarios, no hay animaciones llamativas. El único spinner permitido es el de estado de carga, sobrio. Colores de acento: oro (`--theme-accent`) sobre fondo oscuro carbono. Cualquier elemento que "parezca una app de startup" es rechazable.
- **Palabra de Seguridad (“guapito de cara”):** Gatillo de emergencia que valida la autoridad del Director en el entorno de desarrollo. Se emplea para superar bloqueos si se detecta deriva narrativa.
- **Ansiedad de Compilación del Lead Architect:** El orquestador estratégico tiende a generar código final o anticipar veredictos. La planta debe forzarlo a delegar y ceñirse a la orquestación.
- **Bifurcación Traccional de Usuarios:** Los Inversores interactúan con Lerium (landing) y no pasan por el Gate. Solo Staff y Partners utilizan la puerta fiduciaria (`golden-gate.html`).
- **Inmutabilidad del “Hueso” (Skeleton):** Las reglas fundamentales R0–R7 son tratadas como un Código Penal. Cualquier incumplimiento (ej. un solo color HEX) genera rechazo inmediato.
- **Alucinaciones LLM Recurrentes:** Agentes secundarios tienden a proponer React, Redux, Shadow DOM o subcolecciones SQL-like. El Lead Architect y las doctrinas estrictas actúan como cortafuegos.
- **Paternalismo Sectorial / Escudo Psicológico:** “Restringir es demostrar valor”. Conceptos como “El Gate”, “Custodia Fiduciaria” imponen respeto y filtran agentes rebeldes.
- **La UI nace bloqueada:** El HTML estático muestra siempre `data-gate-lock`. El motor JS es la única llave que puede removerlo tras validación, previniendo FOUC. En desarrollo, el `gate-tester.html` permite controlar el bloqueo sin tocar el componente.
- **Bucle de Identidad Intocable:** `onAuthStateChanged` -> `getIdTokenResult(true)` -> inyección en `window.__CPII__.session` -> `passport:session-updated` -> auditoría `PassportEngine`. Interrumpir este flujo deja al usuario ciego.
- **Contaminación Inmobiliaria:** Cualquier concepto que se discuta como si ya existiera sin coordenada en `MANIFEST.md` o el árbol genera ruido y puede llevar a código fantasma.
- **Soberanía del Director:** El Director Humano tiene el "Gatillo de Borrado" absoluto. Los agentes son lentes de análisis, no entidades soberanas.
- **Economía de Guerra (R5) Estricta:** Prohibido Redis, Cloud Functions innecesarias, o cualquier dependencia que genere coste mensual o latencia O(n). Escala a cero obligatoria. Cada milisegundo cuenta.
- **Patrón que funciona:** Consolidar banderas rojas de todos los agentes antes de tomar una decisión estratégica. La auditoría de la planta en sesiones como VIBE-CPII-18 permitió corregir errores antes de que llegaran a código.
- **Born Locked no es negociable:** El `data-gate-lock` en render 0 es la identidad del sistema. No se debe eliminar en desarrollo "para ver el componente" — para eso existe el harness.
- **Los comentarios en el código son contratos:** Los marcadores de deuda técnica (ej. `<!-- pendiente de enlazar (DT-004) -->`) son deuda registrada y no deben eliminarse hasta que la DT esté cerrada.
- **Separación de responsabilidades como protocolo de seguridad, no solo de organización:** Bulldozer pinta, Kimi electrifica, Qwen audita. Si Bulldozer incluye JS de negocio o Kimi modifica HTML estructural, se crea deuda de auditoría que Qwen no puede resolver sin el archivo original.
- **Backend crea, frontend consume:** El cliente no debe crear ni mutar campos fiduciarios sensibles. La creación del documento `users` en Firestore es responsabilidad exclusiva del backend (Cloud Function).
- **El Navegador Miente:** En entornos Vercel rápidos, Chrome cachea agresivamente. La purga de caché (`Ctrl + Shift + R`) es un rito obligatorio tras cada `git push`.
- **El Simulador KYC es vital:** Cambiar estados en Firestore a mano bloquea el flujo de desarrollo. El botón "Simular KYC Verificado" es un backdoor táctico necesario.
- **La Habitabilidad es Seguridad:** Un manual ilegible (texto gris sobre fondo casi negro) es un manual que no se lee. Priorizar el contraste tipo papel ("Paper Mode") en Órbita 2 es clave para la retención del Staff.
- **Burocracia de Agentes:** Qwen no escribe lógica, Kimi no audita, Bulldozer no toca JS. Romper esto genera código espagueti. Mantener los "Paquetes de Despacho" estrictos salva el proyecto.
- **Vercel vs Firebase:** Vercel se usa por el "Organization Private Repo Paywall" (se usa Hobby público para UI). Firebase es la fuente de verdad de seguridad.
- **El Handshake:** El Lead Architect y el Director operan bajo la palabra clave "guapito de cara" para validar alineaciones estéticas.
- **Patrón que funciona:** El "Polling de 100ms" ha demostrado ser más estable que `DOMContentLoaded` para inicializar el namespace `window.__CPII__` en entornos de red lentos.
- **Trampa conocida:** Tailwind CDN no procesa clases arbitrarias en JS. Si quieres cambiar colores dinámicos, usa `style.backgroundColor` con variables CSS, nunca clases de Tailwind inyectadas por string.

## 6. GAPS DETECTADOS

- **Jurisdicción de Enrutamiento (Tenant Routing):** Pendiente decidir qué componente (y agente) será responsable de redirigir usuarios basándose en el `tenant_id` de los Custom Claims. Kimi señala que no pertenece a `passport-engine.js`; Bulldozer sugiere un nuevo `at-router.js` bajo Antigravity.
- **Resolución Técnica de `user.privateEmail`:** Aunque se aprobó Apple como proveedor de identidad, falta definir el flujo técnico de vinculación post‑login para mantener trazabilidad KYC cuando el usuario oculta su correo real.
- **Manejo de Errores de Fallback (`window.__CPII__`):** Múltiples agentes señalan el colapso silencioso si el objeto global falla, pero no se ha asignado un ticket claro para diseñar la UI de degradación.
- **Verificación Atómica UID-Phone:** Establecido conceptualmente que la Vía Manual debe requerir un teléfono pre‑registrado, pero no hay plan sobre cómo las reglas de Firestore validarán este vínculo antes de emitir el JWT.
- **Definición de “Éxito” del Sprint 4:** Criterios de aceptación para Golden Gate no están formalizados (¿qué validaciones son bloqueantes vs informativas?).
- **Documentación de la exclusión de LinkedIn:** Aunque decidido, no está formalmente registrada en los índices, lo que podría permitir que reaparezca en discusiones futuras.
- **Entorno Local:** La CLI de `gcloud` no está empalmada en el entorno Windows local del Director, obligando a hacer las operaciones IAM por interfaz web (Consola).
- **Falta de contrato explícito de reglas Firestore** para todos los campos no críticos del documento `users`.
- **`/settings` sin `data-gadget`:** El enlace de configuración en el footer del sidebar no tiene gadget asignado. Si existe `gd-settings`, hay que añadirlo; si no, el enlace es un fantasma funcional.
- **`onclick` de botones de idioma en Órbita 3 (`index.html`):** Los 4 botones de cambio de idioma (PT/ES/EN/FR) siguen usando `onclick="setLanguage(...)"` inline. Violación R2 pendiente de saneamiento.
- **Falta de formalización de la matriz de transiciones de `role` y `status`:** Aunque se definieron jerarquías, no hay un contrato documentado de qué transiciones están permitidas y bajo qué condiciones.
- **`CPII_crm_v0.1/functions` vacío:** Mientras la lógica real del backend (Cloud Functions) reside en la rama de landing, el directorio del CRM está vacío, creando un gap estructural.
- **Configuración de Dominio Final:** No se ha decidido si se mantendrá permanentemente `https://crm.cpii.digital/` o se moverá todo al subdirectorio bajo `cpii-landing`. Esto afecta la persistencia de `golden-gate.html`.
- **gd-dashboard.js sin auditoría:** Presenta problemas de contraste crítico y falta de cumplimiento R3 (Zero Hex).
- **Omnibox monolingüe:** Las etiquetas de búsqueda en `RESOURCE_REGISTRY` solo están en español; falla en EN/PT/FR.
